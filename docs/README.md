# Fitness Platform 项目文档中心

本目录把产品 PRD 转换为可以直接指导设计、开发、联调和验收的工程文档。PRD 回答“产品要什么”，这里的文档回答“业务规则如何统一”“接口如何约定”“开发按什么顺序完成”。

## 文档导航

1. [业务逻辑设计](./01_业务逻辑设计.md)
   - 领域边界、核心规则、状态机、时间语义、权限、幂等、Agent、RAG、训练闭环。
2. [API 接口契约](./02_API接口契约.md)
   - 全局协议、错误码、DTO、REST/SSE 接口、权限及幂等要求。
3. [全周期开发任务与验收清单](./03_全周期开发任务与验收清单.md)
   - 从工程基线到上线演示的阶段任务、依赖、交付物和验收标准。

## 文档优先级

出现冲突时按以下顺序处理：

1. 当前版本 PRD 的产品边界；
2. 本目录中的业务不变量和接口契约；
3. 已确认的技术设计记录；
4. 当前代码实现。

代码与文档不一致时，不默认代码正确。先判断是实现缺陷还是文档需要修订，再提交变更。

## 当前核心交付范围

简历项目的最小完整交付为：

```text
V1 饮食记录 MVP
→ V1.1 快速记录与食品搜索
→ V1.2 Analytics / Export
→ V2 Fitness Agent Core
→ V2.1 RAG
```

V3、V3.5、V4 作为完整产品第二主线纳入长期任务清单。Future 中的社交、教练、健康平台接入、视觉营养识别不属于核心毕业条件。

## 学习与验收约定

- 学习者独立编写所有业务代码和测试。
- 验收者只审查、解释问题和给出下一任务，不代写实现。
- 每个任务尽量保持一次提交可完成、可运行、可回滚。
- “接口能返回 200”不等于通过；业务规则、权限、异常、幂等和测试都要验收。
- 未通过的任务先修正，不带病进入依赖它的后续阶段。
