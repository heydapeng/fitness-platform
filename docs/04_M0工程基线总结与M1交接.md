# M0 工程基线总结与 M1 交接

## 1. 文档目的

本文记录 Fitness Platform 在 M0 阶段完成的工程工作、解决的问题、最终运行方式、验收结果，以及进入 M1 前必须保持的基线。

M0 只解决“项目能否被稳定构建、测试和启动”，不实现新的业务功能。

---

## 2. M0 最终运行架构

```text
Windows
├─ IDEA
│  └─ Spring Boot（local profile，端口 8080）
│
└─ localhost
   ├─ 3307 → WSL Docker → fitness-platform-mysql-1:3306
   └─ 6380 → WSL Docker → fitness-platform-redis-1:6379
```

约定：

- Spring Boot 直接在 Windows IDEA 中运行，不放入 Docker；
- MySQL 8 和 Redis 7 运行在 WSL Docker 中；
- Windows 通过 `localhost:3307` 访问项目 MySQL；
- Windows 通过 `localhost:6380` 访问项目 Redis；
- 项目基础设施统一由根目录 `compose.yaml` 管理；
- 旧的 `mysql:3306`、`redis:6379` 容器不属于本项目 M0 环境；
- 本地密码只存在于被 Git 忽略的配置文件中。

## 4. M0 解决的主要问题

### 4.1 Windows Maven Wrapper 无法启动

现象：

```text
Cannot index into a null array
Cannot start maven from wrapper
```

处理：修复 Wrapper 对普通 Maven 本地仓库目录的链接目标判断。

结果：Windows 下 Maven Wrapper 可以正常下载并启动固定版本 Maven。

### 4.2 前端 Vitest TypeScript 配置缺失

现象：TypeScript 配置引用了不存在的 `tsconfig.vitest.json`，导致构建基线失败。

处理：恢复正确的 Vitest TypeScript 配置，没有删除测试配置来绕过问题。

结果：类型检查、单元测试和生产构建全部通过。

### 4.3 测试依赖本机数据库

风险：测试结果会受到开发者本机数据库、历史数据和密码影响。

处理：改为 Testcontainers 自动提供独立 MySQL 8。

结果：测试可重复运行，并能从空库验证全部 Flyway migration。

### 4.4 项目 MySQL 启动后立即退出

现象：

```text
docker compose exec mysql ...
service "mysql" is not running
```

原因：`.env` 曾把 `DB_USERNAME` 写成带前导空格的 root。`compose.yaml` 会把它传给 MySQL 镜像的 `MYSQL_USER`，而官方镜像不允许通过 `MYSQL_USER` 创建 root 用户，因此容器退出。

最终约定：

- Compose 初始化使用普通 `fitness` 用户；
- root 密码由 `MYSQL_ROOT_PASSWORD` 设置；
- Windows IDEA 的 `application-local.yaml` 可以按本地需要使用 root；
- 两套配置职责不同，不能把 `MYSQL_USER` 设置为 root；
- `.env` 的键值两侧不添加多余空格。

结果：项目 MySQL 和 Redis 均为 `healthy`，Windows 后端可以正常连接。

### 4.5 旧容器与项目容器混淆

本机还可能存在旧容器：

```text
mysql:3306
redis:6379
```

它们不属于本项目 M0 环境。

M0 只认由当前 `compose.yaml` 创建的项目容器和端口：

```text
fitness-platform-mysql-1 → 3307
fitness-platform-redis-1 → 6380
```

这样可以避免依赖开发者机器上的历史容器。

```bash

```

### 5.2 验证 Redis

```bash
docker compose exec redis redis-cli ping
```

预期：

```text

```

### 5.3 启动后端

在 IDEA 中：

1. 选择 `FitnessSystemApplication`；
2. 激活 `local` profile；
3. 点击 Run；
4. 确认 Flyway 和 Tomcat 日志正常。

### 5.4 停止基础设施

```bash
docker compose down
```

该命令保留数据卷。

只有明确需要清空本地数据库时才执行：

```bash
docker compose down -v
```

## 7. 进入 M1 的边界

M1 主题：公共后端基础。

开始 M1 后，不再随意修改以下 M0 基线：

- Java 21；
- Maven Wrapper；
- MySQL 8；
- Redis 7；
- Flyway migration 规则；
- Testcontainers 测试隔离；
- CI 基线；
- 本地配置不提交 Git。

M1 按以下顺序进行：

1. T1.1：清理重复公共类型；
2. T1.2：统一响应模型；
3. T1.3：建立领域异常体系；
4. 后续任务以全周期开发任务与验收清单为准。

M1 的第一项工作是检查并处理重复的 `Result`、`MealType` 及旧包残留。该工作属于业务公共基础整理，不应再改动 M0 的本地运行拓扑。
