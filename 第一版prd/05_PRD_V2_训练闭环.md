# Fitness Nutrition Platform — PRD V2：训练闭环

## 一、版本概述

V2 将平台从“饮食记录工具”扩展为“饮食 + 训练”一体化平台。

目标是让用户完成完整训练闭环：

```text
查看动作 → 创建训练计划 → 开始一次训练 → 按组记录 → 结束训练 → 查看本次结果
```

V2 重点解决“能不能完整记录一次训练”，不优先做高级统计和 AI 自动编排。

## 二、用户核心问题

- 今天应该练哪些动作？
- 每个动作目标做几组、几次、多少重量？
- 训练时能不能快速逐组记录？
- 一次训练中途退出后能不能继续？
- 完成后能看到训练时长和总量吗？
- 动作怎么做、练哪里、有哪些注意事项？

## 三、版本目标

1. 建立标准动作库；
2. 支持动作说明、目标肌群与合法媒体资源；
3. 支持用户完全自定义训练计划，包括周期、每周训练日、动作、组次和训练目标；
4. 支持从计划启动一次实际训练；
5. 支持按动作、按组记录重量、次数、RPE/RIR；
6. 支持暂停/继续/结束训练；
7. 训练事实与计划模板分离；
8. 为 V2.5 的 PR/容量统计提供可靠原始数据。

## 四、功能范围

- 动作库；
- 动作分类/肌群；
- 动作详情；
- 动作媒体；
- 训练计划；
- 计划中的动作与目标组次；
- 训练 Session；
- Workout Set 逐组记录；
- 训练计时；
- 本次训练总结；
- 训练历史基础列表。

本版本不重点实现：PR 排行、长期训练统计、教练下发、AI 自动训练计划。

> V2 的训练计划必须先作为独立、完整、可手动操作的业务能力存在。V5 的 AI 制定计划只能调用这套已有计划能力，不能另外保存一份“AI 文本计划”。

## 五、动作库

### 1. 动作列表

#### 搜索与筛选

- 中文/英文动作名搜索；
- 目标肌群筛选；
- 器械筛选；
- 难度筛选；
- 状态筛选仅管理员可见。

#### 列表字段

- 动作名称；
- 主要肌群；
- 次要肌群；
- 器械；
- 难度；
- 缩略图（如有）。

### 2. 动作详情

展示：

- 中文名/英文名；
- 动作简介；
- 主要肌群；
- 次要肌群；
- 所需器械；
- 动作步骤；
- 注意事项；
- 常见错误；
- 图片/GIF/视频（如合法可用）。

### 3. 媒体与版权规则

- 不直接抓取未知版权图片/GIF 用于正式产品；
- 资源需要明确来源与授权状态；
- 无可用媒体时动作仍可正常使用；
- 媒体异常不应阻塞训练记录。

## 六、训练计划

### 1. 功能定位

训练计划是用户未来一段时间的训练安排模板，解决“哪天练什么、每个动作做几组几次”的问题。

计划可以完全由用户手动创建。V5 上线后，AI 也可以根据用户自然语言生成计划草稿，但最终仍保存为这里定义的同一种训练计划。

### 2. 计划列表

展示：

- 计划名称；
- 训练目标：增肌/力量/减脂辅助/体能/自定义；
- 开始日期；
- 结束日期或预计周期；
- 每周训练天数；
- 当前状态；
- 当前第几周；
- 最近一次执行时间；
- 操作。

状态建议：

- 草稿；
- 已启用；
- 已暂停；
- 已完成；
- 已归档。

同一用户默认只允许一个“当前主计划”处于启用状态；如未来支持并行计划，应另行定义使用规则。

### 3. 新建计划基础信息

字段：

- 计划名称；
- 训练目标；
- 开始日期；
- 计划周期，例如 4/8/12 周；
- 每周预计训练天数；
- 可训练星期；
- 每次预计训练时长；
- 训练场景：健身房/家庭/户外/混合；
- 备注。

用户不需要一次把所有信息填满才能保存草稿，但启用计划前必须具备可执行的训练日和动作内容。

### 4. 周训练日安排

用户可按星期配置：

```text
周一：Push
周二：Pull
周三：休息
周四：Legs
周五：休息
周六：Upper
周日：休息
```

每个训练日可配置：

- 训练日名称；
- 对应星期或周期中的第几天；
- 目标肌群；
- 动作列表；
- 预计时长；
- 训练日备注。

支持：

- 新增训练日；
- 删除训练日；
- 复制训练日；
- 调整星期；
- 拖拽排序；
- 设置休息日。

### 5. 计划动作配置

每个动作可配置：

- 动作；
- 顺序；
- 目标组数；
- 目标次数或次数范围；
- 目标重量（可选）；
- 目标 RPE/RIR（可选）；
- 组间休息建议（可选）；
- 是否为热身动作；
- 动作备注。

### 6. 自定义进阶规则

用户可选择简单的进阶备注，例如：

- 达到次数上限后下次加重量；
- 每周增加 1 次；
- 保持 RIR 2；
- 自定义文字规则。

V2 不要求系统自动复杂编排周期化，但要允许用户保存自己的计划意图。

### 7. 计划编辑

支持：

- 修改计划名称和目标；
- 修改训练星期；
- 增删动作；
- 调整动作顺序；
- 修改组次/重量/RPE；
- 复制整个计划；
- 从已有计划创建新版本；
- 暂停/继续计划；
- 提前结束计划。

### 8. 历史事实保护

用户今天完成训练后，明天再修改训练计划：

- 已完成的训练 Session 不应被重写；
- 历史组记录保持当时实际训练事实；
- 新计划内容只影响后续尚未发生的训练安排。

### 9. 计划切换

当用户启用另一份计划时：

- 明确提示当前启用计划；
- 用户确认后，旧计划可进入暂停/结束状态；
- 不删除旧计划历史；
- Dashboard “今日训练”切换到新计划。

### 10. 计划冲突

如果用户将两个训练日都安排到同一日期，系统允许用户修改，但应提示存在冲突。

计划本身是用户安排，不应因为平台“觉得不合理”而擅自重排。

### 11. 为 AI 计划预留的产品边界

V2 必须让训练计划的新增、修改、复制、启停和动作配置都形成稳定业务能力。

V5 用户可以说：

> “给我做一个每周四练的增肌计划，我周三周五没时间。”

AI 生成的结果必须进入同一训练计划模型，并允许用户继续在传统页面手动编辑。

用户也可以反向操作：先手动建计划，再让 AI 修改其中一部分。

## 七、开始训练

### 1. 入口

- 今日计划；
- 训练计划详情；
- 手动开始自由训练（可选）。

### 2. 启动时展示

- 训练名称；
- 动作总数；
- 预计内容；
- 开始时间；
- “开始训练”按钮。

### 3. 未完成训练恢复

如果用户存在未结束 Session：

- 进入训练页时提示“你有一场未完成训练”；
- 可继续；
- 可确认放弃；
- 不应无提示创建多个重复 Session。

## 八、训练进行页

### 1. 页面结构

按动作分组，每个动作展示：

- 动作名称；
- 目标组次；
- 上一次同动作参考（可选）；
- 当前各组记录；
- 添加一组；
- 动作说明快捷入口。

### 2. 组记录字段

每一组可填写：

- 重量；
- 次数；
- RPE（可选）；
- RIR（可选）；
- 组类型：正常组/热身组等；
- 是否完成。

### 3. 组操作

- 新增组；
- 复制上一组数值；
- 修改；
- 删除；
- 标记完成。

### 4. 训练计时

- 记录开始时间；
- 训练中显示已用时；
- 用户结束训练后记录结束时间和总时长；
- 页面刷新或短暂离开不应丢失已保存组记录。

## 九、结束训练与总结

### 1. 结束前检查

如果存在尚未完成的计划组：

- 提示“还有未完成组”；
- 用户可以继续训练；
- 也可以确认结束，本次按实际完成事实保存。

### 2. 总结内容

- 开始/结束时间；
- 总时长；
- 完成动作数；
- 完成组数；
- 总训练容量（基础计算）；
- 训练备注。

### 3. 训练容量

基础口径：

> 单组容量 = 重量 × 次数

本次训练容量 = 所有纳入统计的完成组之和。

热身组是否计入总容量需要产品口径固定，默认可单独标识并在 V2.5 进一步规范。

## 十、训练历史

### 1. 列表

展示：

- 日期；
- 训练名称；
- 时长；
- 动作数；
- 完成组数；
- 总容量；
- 详情入口。

### 2. 详情

按动作展示所有实际完成组，不以当前训练计划模板重新解释历史。

## 十一、管理员动作维护

管理员可：

- 新增动作；
- 编辑动作说明；
- 维护主要/次要肌群；
- 维护器械；
- 上传/关联授权媒体；
- 启用/停用动作。

动作停用后：

- 新计划不可继续选择；
- 已有历史训练仍正常展示；
- 已有未结束计划中如引用停用动作，应明确提示用户处理，而不是静默删除。

## 十二、业务规则与约束

1. 训练计划是“计划”，训练 Session 是“实际发生事实”。
2. 修改计划不回写历史 Session。
3. 每组实际数据由用户确认，不用计划目标覆盖。
4. 动作被停用不破坏历史。
5. 同一用户的训练数据严格隔离。
6. 训练进行中异常退出后应尽量恢复已保存内容。
7. 公式型指标由系统统一计算，不允许前端各页面各算一套。

## 十三、异常与空状态

| 场景 | 系统行为 |
| --- | --- |
| 没有训练计划 | 引导创建计划或自由训练 |
| 动作搜索无结果 | 展示空状态 |
| 计划引用停用动作 | 标记并引导替换 |
| 未完成训练再次开始 | 先提示恢复/放弃 |
| 重量/次数非法 | 阻止该组完成 |
| 网络中断 | 已成功保存的组不丢失，未保存内容保留在页面 |
| 结束训练时仍有未完成组 | 二次确认 |

## 十四、验收标准

- 能搜索并查看动作详情；
- 能创建至少一个包含多个动作的训练计划；
- 能从计划启动 Session；
- 能逐组记录重量和次数；
- 能编辑/删除某一组；
- 能结束训练并看到总结；
- 修改训练计划不改变已完成历史；
- 动作停用不破坏历史；
- 用户数据隔离正确。

## 十五、技术约束（简版）

- 训练计划与训练事实分离建模；
- 训练容量等确定性计算由统一后端业务层负责；
- 媒体存储可使用对象存储，但不是训练记录核心依赖；
- 为 V2.5 统计和后续 AI Read Tool 保留稳定查询能力。
