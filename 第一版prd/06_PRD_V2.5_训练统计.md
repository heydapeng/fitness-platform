# Fitness Nutrition Platform — PRD V2.5：训练统计与进步分析

## 一、版本概述

V2 解决“把训练记下来”，V2.5 解决“从训练记录里看懂进步”。

本版本重点是建立稳定、可解释的训练指标口径，而不是追求大量图表。

## 二、用户核心问题

- 我卧推最近有没有进步？
- 我的最高重量是多少？
- 90kg×5 和 100kg×1 应该怎么比较？
- 这周我练了几次、做了多少组？
- 每周训练容量是在上升还是下降？
- 哪些肌群最近练得少？

## 三、版本目标

1. 提供动作历史；
2. 区分 Weight PR、Rep PR、Estimated 1RM PR；
3. 提供训练容量和组数统计；
4. 提供训练频率和时间趋势；
5. 提供基础肌群训练量视图；
6. 所有指标有固定口径并可追溯到原始训练记录。

## 四、训练统计首页

### 1. 概览卡片

可展示：

- 本周训练次数；
- 本周完成组数；
- 本周总训练时长；
- 本周总容量；
- 最近 PR 数量；
- 连续训练周数（可选）。

### 2. 时间筛选

- 本周；
- 最近 4 周；
- 最近 12 周；
- 自定义日期范围。

## 五、动作训练历史

### 1. 动作选择

用户可从自己训练过的动作中选择一个动作查看历史。

### 2. 展示内容

- 最近训练日期；
- 每次训练的最高重量；
- 主要工作组；
- 总组数；
- 总次数；
- 估算 1RM；
- 历史 PR 标记。

### 3. 图表

可切换：

- 最高重量趋势；
- 估算 1RM 趋势；
- 训练容量趋势。

## 六、PR 规则

### 1. Weight PR

某动作完成组中，用户历史成功完成的最高重量。

### 2. Rep PR

需要按重量或次数组合定义，不允许把所有高次数组混成一个“次数最大”而失去意义。

建议产品展示：

- 某重量下最高完成次数；
- 或常见次数区间下的最佳重量。

### 3. Estimated 1RM PR

使用统一估算公式，从重量和次数估算理论 1RM。

页面必须标注“估算”，不得与真实 1RM 测试混为一谈。

### 4. PR 识别规则

- 仅统计有效完成组；
- 热身组是否计入由统一口径决定，默认不作为 PR；
- 数据被用户修改/删除后，PR 应重新计算；
- 不同动作不跨动作比较 PR。

## 七、训练容量统计

### 1. 单组容量

重量 × 次数。

### 2. Session 容量

纳入统计的所有完成组容量之和。

### 3. 周/月趋势

展示：

- 每周总容量；
- 每月总容量；
- 同动作容量；
- 可按训练计划/动作筛选。

### 4. 解释限制

训练容量上升不自动等于训练效果更好；产品不输出医学/训练学绝对结论，只提供事实趋势。

## 八、训练频率与组数

### 1. 训练频率

- 每周训练 Session 数；
- 每月训练 Session 数；
- 平均每周次数。

### 2. 组数

- 每周总完成组数；
- 按动作统计；
- 按主要肌群统计。

### 3. 肌群统计规则

动作存在主要/次要肌群映射时：

- 主要肌群计入主要统计；
- 次要肌群可单独展示贡献，不简单重复当作完整主工作组；
- 产品应固定口径，避免不同页面同一周结果不同。

## 九、训练日历

按月展示：

- 哪些日期完成训练；
- 训练名称；
- 训练时长；
- 是否产生 PR。

点击日期进入该次训练详情。

## 十、异常与边界

| 场景 | 系统行为 |
| --- | --- |
| 用户只有一次训练 | 展示事实，不输出明显趋势结论 |
| 某动作数据不足 | 不展示 PR 趋势或标注样本不足 |
| 用户修改历史组 | 对相关统计重新计算 |
| 删除历史 Session | 统计同步扣除 |
| 重量为 0 的自重动作 | 不强行使用重量容量解释，允许特殊口径 |
| 时间范围内无数据 | 展示空状态与记录训练入口 |

## 十一、业务规则与约束

1. 所有统计都必须能回溯到 V2 原始训练事实。
2. PR 定义固定，不能为了“好看”在不同页面改变。
3. Estimated 1RM 与真实 1RM 明确区分。
4. 指标缺少适用前提时宁可不展示，也不输出误导结果。
5. 数据被编辑/删除后统计必须一致更新。
6. 后续教练和 AI 使用的统计应复用同一口径。

## 十二、验收标准

- 可查看某动作历史；
- 能正确标记最高重量 PR；
- 能计算并展示估算 1RM；
- 能查看周/月训练容量；
- 能查看训练频率；
- 能查看主要肌群组数；
- 修改历史组后统计正确变化；
- 无数据和数据不足时不产生误导展示。

## 十三、技术约束（简版）

- 指标公式统一由后端统计服务维护；
- 不要求 V2.5 建复杂实时数仓，先基于业务训练记录聚合；
- 统计口径需要有版本意识，避免未来算法变化无法解释历史。
