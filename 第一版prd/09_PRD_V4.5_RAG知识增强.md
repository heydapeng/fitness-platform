# Fitness Nutrition Platform — PRD V4.5：RAG 健身知识增强

## 一、版本概述

V4 已经让 AI 可以读取用户真实数据，但对“为什么”和“应该如何理解”的回答仍缺少稳定知识来源。

V4.5 引入 RAG，将经过筛选和审核的健身、营养、训练知识作为 AI 回答依据，使回答从“只有模型常识”升级为“可检索、可引用、可追溯”。

## 二、用户核心问题

- “减脂时蛋白质为什么重要？”
- “RPE 8 大概是什么意思？”
- “训练后碳水有什么作用？”
- “我今天蛋白质还差很多，晚餐怎么补比较合理？”
- “这个建议的依据是什么？”

## 三、版本目标

1. 建立可管理的健身知识库；
2. 支持文档切分与向量检索；
3. 对自然语言查询进行必要的 Query Rewrite；
4. 对召回候选进行 Rerank；
5. 回答展示知识来源；
6. 支持知识版本、审核和失效管理；
7. 为 V5 Tool + RAG 融合提供可靠知识底座。

## 四、知识范围

可包含：

- 基础营养学；
- 热量平衡；
- 蛋白质/碳水/脂肪；
- 减脂和增肌基础知识；
- 力量训练基础；
- RPE / RIR；
- 恢复与睡眠；
- 常见训练问题；
- 合法来源的研究解读；
- 经授权的教练内容；
- 平台 FAQ。

本版本不将用户个人饮食、体重、训练记录放进知识库替代 MySQL。

## 五、知识内容管理

### 1. 文档信息

每份知识文档至少需要记录：

- 标题；
- 分类；
- 主题；
- 内容类型；
- 来源；
- 作者；
- 发布日期；
- 语言；
- 版本；
- 授权/版权状态；
- 审核状态；
- 生效/失效状态。

### 2. 审核状态

建议：

- DRAFT：草稿；
- REVIEWING：审核中；
- APPROVED：可用于回答；
- REJECTED：不采用；
- EXPIRED：过期停用。

AI 默认只能检索 APPROVED 且当前有效内容。

### 3. 内容更新

- 新版本文档上线后，旧版本可标记过期；
- 不能无记录覆盖原来源；
- 管理员应能知道某条知识来自哪个版本。

## 六、RAG 问答体验

### 1. 普通知识问题

用户：

> “RIR 2 是什么意思？”

系统：

- 检索训练知识；
- 选取最相关内容；
- 生成简洁说明；
- 提供来源入口。

### 2. 查询改写

对口语问题可先转为更适合检索的查询。

示例：

> “最后两下特别吃力但还能做，这算几 RIR？”

系统可以改写为与“RIR 定义/剩余次数”相关的检索问题，但最终回答仍应与原问题保持一致。

### 3. Rerank

当初步检索返回多个相关文档时，对候选内容二次排序，优先使用最相关、已审核、当前有效的知识。

从产品角度要求：

- 不因为某文档向量相似就直接把它当最终依据；
- 低相关结果应被过滤；
- 没有可靠知识时要承认不足。

## 七、来源与引用

### 1. 回答引用

知识增强回答至少支持展示：

- 来源标题；
- 来源类型；
- 发布/版本信息；
- 可访问的来源链接（如允许）。

### 2. 引用规则

- 不引用未审核文档；
- 不伪造来源；
- 多来源时只展示真正参与回答的主要来源；
- 过期知识不继续作为默认依据。

## 八、RAG + 用户业务数据的初步融合

虽然完整编排放在 V5，但 V4.5 可以支持简单混合问题。

示例：

> “我今天蛋白质还差多少？蛋白质有什么作用？”

系统分别获取：

- Tool：今天蛋白质差额；
- RAG：蛋白质相关审核知识。

回答要区分：

- “你的数据”：来自业务系统；
- “知识说明”：来自知识库；
- “模型表达”：只负责组织语言。

## 九、知识库管理后台

管理员可：

- 新增/导入文档；
- 编辑文档基础信息；
- 设置分类/主题；
- 提交审核；
- 通过/驳回；
- 标记过期；
- 查看当前索引状态；
- 查看检索测试结果（可选）。

本 PRD 不规定具体向量数据库实现。

## 十、版权与内容安全

- 不默认拥有互联网上文章、课程、论文全文的再分发权；
- 文档必须记录来源与授权状态；
- 付费课程、商业教练内容需要明确授权；
- 研究论文可优先使用允许引用/公开摘要与合法内容；
- 如果内容有效性存疑，应阻止进入 APPROVED。

## 十一、异常与边界

| 场景 | 系统行为 |
| --- | --- |
| 没有检索到高相关知识 | 明确说明知识库没有足够依据 |
| 检索到过期文档 | 默认排除 |
| 多文档观点不一致 | 说明存在差异并展示来源，不强行合并成唯一真理 |
| 文档无授权状态 | 不进入正式知识检索 |
| RAG 服务暂时不可用 | 业务 Tool 查询仍可继续，知识部分降级 |
| 用户问个人事实 | 优先 Tool/MySQL，不从知识库猜 |

## 十二、业务规则与约束

1. MySQL 保存用户事实，RAG 保存非结构化知识，职责不能互换。
2. 只有审核通过且有效的内容参与正式回答。
3. 检索结果不等于答案，仍需相关性筛选与重排。
4. 回答应保留来源可追溯性。
5. 知识更新需要版本意识。
6. 用户业务数据永远优先于 Memory 和 RAG 中可能过时的上下文。

## 十三、验收场景

- 能导入并审核一份营养知识文档；
- 用户提问后能召回相关内容；
- Query Rewrite 对口语查询有帮助；
- Rerank 后使用的内容相关度明显合理；
- 回答能展示来源；
- 将文档标记 EXPIRED 后不再作为默认引用；
- 用户问实时个人数据时仍从 Tool 获取；
- RAG 不可用时基础业务 AI 查询可降级运行。

## 十四、技术约束（简版）

- 基本链路：Document → Chunk → Embedding → Retrieval → Rerank → Context → LLM；
- 支持 Query Rewrite 与 Metadata Filter；
- 向量检索能力独立于 MySQL 交易数据；
- 技术选型可后续决定，不在 PRD 固定具体向量数据库。
