# Fitness Nutrition Platform — PRD V1.2：记录媒体与数据导出

## 一、版本概述

V1/V1.1 已解决“饮食能不能准确、快速记录”的问题。V1.2 进一步解决两个长期使用问题：

1. 健身用户不仅想记录数字，也习惯拍下当天吃的食物，形成可回看的饮食记忆；
2. 用户希望自己的健身数据能够随时导出，用于复盘、备份、分享给教练，或迁移到其他工具。

因此本版本增加饮食图片和用户数据导出能力。

本版本不负责 AI 自动识别图片中的食物，也不负责 AI 解析任意历史文件导入；这两类智能能力放在 V5 Fitness Agent。

## 二、用户核心问题

- 我记录这顿饭时能不能顺手拍张照片？
- 过几个月以后，我能不能回看当时到底吃了什么？
- 我想把最近三个月每日摄入导出来做自己的分析。
- 我想把体重和围度变化给教练看，能不能导出？
- 我导出饮食记录时，之前上传的食物照片能不能一起带走？
- 如果以后不用这个平台，我的数据能不能完整拿出来？

## 三、版本目标

1. 每条饮食记录或每餐可关联用户上传的食物图片；
2. 图片上传不能阻塞核心饮食记录；
3. 用户可按时间范围导出关键业务数据；
4. 导出内容可选择饮食、身体、训练等数据域；
5. 有关联图片时可选择将图片一起打包；
6. 导出结果结构清晰，可供用户自己查看或后续再次处理；
7. 为 V5 “AI 一句话触发导出”和“AI 历史数据导入”建立统一的数据边界。

## 四、功能范围

本版本包含：

- 饮食记录图片上传；
- 图片预览、删除和替换；
- 饮食历史中的图片展示；
- 数据中心；
- 按日期范围导出；
- 选择数据类型；
- 结构化数据文件导出；
- 图片附件打包导出；
- 导出任务历史；
- 导出失败重试；
- 用户数据范围说明。

本版本不包含：

- 图片自动识别食物和重量；
- AI OCR 导入旧记录；
- AI 自动把任意 Excel/PDF 映射成系统字段；
- AI 对导出数据做自动报告解读。

## 五、饮食图片记录

### 1. 功能定位

图片是饮食记录的补充证据和生活记录，不替代食品、重量、餐次等结构化字段。

即使图片上传失败，用户仍应可以正常保存饮食记录。

### 2. 上传入口

以下场景可上传图片：

- 新增饮食记录页面；
- 多食品一次添加页面；
- 已有饮食记录详情/编辑页；
- Dashboard 当餐快捷记录区域（可选）。

### 3. 上传方式

支持：

- 手机拍照；
- 相册选择；
- 桌面端选择本地图片；
- 一次选择多张图片。

### 4. 图片数量

产品建议：

- 单条饮食记录默认最多 5 张；
- 一餐多食品场景可允许图片关联到整餐，而不是强制每张图片归属某一个食品；
- 后续如数据量较大可调整上限。

### 5. 图片展示

饮食记录详情展示：

- 缩略图；
- 点击查看大图；
- 图片上传时间；
- 删除图片；
- 补传图片。

历史列表可显示第一张缩略图作为视觉提示。

### 6. 图片与记录关系

产品需支持两种理解：

#### 单条食品图片

例如“200g 鸡胸肉”单独拍照。

#### 整餐图片

例如用户拍一张午餐餐盘，其中包含米饭、鸡胸、西兰花。

若 V1.1 多食品一次添加形成一餐，图片优先支持关联整餐，避免用户重复上传同一张图片。

## 六、图片管理规则

### 1. 删除饮食记录

用户删除饮食记录时：

- 页面提示该记录关联图片也将不再出现在饮食历史中；
- 是否立即物理删除图片由存储策略决定，但用户端应视为已删除；
- 已经生成的历史导出包不受后续删除影响。

### 2. 修改饮食记录

修改重量、餐次、日期时，原图片默认继续跟随该记录/餐次。

如果用户更换成完全不同的食品，可提示：

> “当前记录包含 2 张原食物图片，是否保留？”

### 3. 图片失败

如果图片上传失败：

- 饮食文本数据仍可保存；
- 明确提示“记录已保存，图片上传失败”；
- 提供重新上传入口。

### 4. 隐私

- 图片默认仅当前用户可见；
- V3 教练只能在用户明确授权相关饮食数据后查看；
- 不默认将用户食物图片用于公开社区或训练模型用途。

## 七、数据中心

### 1. 功能定位

数据中心用于用户查看“平台保存了我哪些健身数据”，并发起导出。

入口建议：

```text
个人中心 → 我的数据
```

也可在设置页提供“导出我的数据”入口。

### 2. 数据概览

展示当前用户已有数据类型和大致范围：

- 饮食记录：最早日期 / 最新日期 / 总记录数；
- 饮食图片：图片数量；
- 营养目标：历史目标数量；
- 身体数据：V1.5 上线后显示；
- 身体进度照片：如已启用则显示；
- 训练数据：V2 上线后显示；
- 训练统计：V2.5 上线后可导出派生报表；
- 教练数据：按授权与隐私规则处理。

未上线的数据域不展示无效入口。

## 八、创建导出任务

### 1. 日期范围

支持：

- 最近 7 天；
- 最近 30 天；
- 最近 90 天；
- 本月；
- 本年；
- 自定义日期范围；
- 全部历史。

### 2. 数据类型选择

用户可勾选：

- 每日饮食明细；
- 每日营养汇总；
- 营养目标历史；
- 身体测量与趋势基础数据；
- 身体进度照片；
- 训练计划；
- 训练历史；
- 训练组记录；
- 训练统计摘要；
- 饮食图片。

系统只显示当前版本已经存在的数据域。

### 3. 导出用途模式

可提供三种产品模式：

#### 数据分析版

偏结构化，适合用户自行分析。

内容包括：

- 明细表；
- 每日汇总；
- 日期、数值和单位字段清晰。

#### 人类阅读版

生成易读的阶段总结文件，包含：

- 体重变化；
- 围度变化；
- 每日/周平均营养；
- 训练频率；
- 关键趋势图（后续版本）。

#### 完整备份版

包含用户选中的结构化数据和所有关联媒体文件。

### 4. 图片选项

如果用户选择饮食数据且所选范围内存在食物图片：

提示：

> “检测到该时间范围包含 86 张饮食图片，是否一并导出？”

选项：

- 仅数据；
- 数据 + 图片；
- 取消。

## 九、导出内容要求

### 1. 每日饮食摄入

至少包含：

- 日期；
- 餐次；
- 食品名称；
- 重量；
- 热量；
- 蛋白质；
- 脂肪；
- 碳水；
- 备注；
- 是否有图片；
- 图片文件关联标识。

### 2. 每日营养汇总

至少包含：

- 日期；
- 当日目标热量及宏量营养；
- 当日实际摄入；
- 剩余/超出；
- 完成率。

### 3. 身体变化

V1.5 上线后可包含：

- 日期；
- 体重；
- 体脂；
- 肌肉量；
- 腰围；
- 胸围；
- 臂围；
- 大腿围；
- 备注；
- 是否有关联身体照片。

### 4. 训练数据

V2/V2.5 上线后可包含：

- 训练日期；
- 计划名称；
- 动作；
- 组数；
- 重量；
- 次数；
- RPE/RIR；
- 训练时长；
- 总容量；
- PR 等派生信息。

## 十、图片打包导出

### 1. 产品目标

用户选择“数据 + 图片”后，系统应输出一个完整可下载的导出包。

### 2. 图片组织方式

建议按日期和业务类型组织，用户解压后能够理解：

```text
饮食图片/
  2026-09-01/
  2026-09-02/
身体进度照片/
  2026-09-01/
```

PRD 不规定具体文件系统实现，但要求图片与结构化记录之间能够对应。

### 3. 文件命名

导出时应避免全部使用随机文件名导致用户无法理解。

建议文件名至少包含：

- 日期；
- 餐次或记录类型；
- 顺序号。

## 十一、导出任务状态

导出较大时可能不是瞬间完成，因此用户需看到状态：

- 准备中；
- 处理中；
- 已完成；
- 失败；
- 已过期。

### 1. 已完成

显示：

- 创建时间；
- 数据范围；
- 包含内容；
- 文件大小；
- 下载按钮。

### 2. 失败

- 明确说明失败；
- 不让用户误以为数据丢失；
- 可重新创建同条件导出。

### 3. 下载有效期

大文件下载链接可设置有效期。过期后数据本身仍在系统中，用户可以重新生成。

## 十二、典型用户场景

### 场景 A：记录午餐并拍照

```text
用户添加午餐
→ 选择米饭、鸡胸肉、西兰花
→ 输入重量
→ 上传一张餐盘照片
→ 保存
→ Dashboard 营养立即更新
→ 历史记录显示照片缩略图
```

### 场景 B：图片失败但记录成功

```text
用户保存饮食
→ 数据保存成功
→ 图片网络上传失败
→ 页面提示“饮食已记录，图片上传失败”
→ 用户稍后补传
```

### 场景 C：导出三个月饮食

```text
用户进入“我的数据”
→ 选择最近90天
→ 勾选每日饮食明细 + 每日营养汇总
→ 系统发现存在饮食图片
→ 用户选择“数据+图片”
→ 创建导出任务
→ 完成后下载完整包
```

### 场景 D：给教练导出身体变化

```text
用户选择近6个月
→ 勾选身体数据与身体进度照片
→ 生成阅读版/完整包
→ 用户自行发送给教练
```

## 十三、异常与边界

| 场景 | 系统行为 |
| --- | --- |
| 图片格式不支持 | 提示重新选择，不影响结构化记录 |
| 图片过大 | 压缩或提示限制 |
| 一次上传过多 | 提示上限 |
| 导出范围无数据 | 提示无可导出数据，不生成空包 |
| 只选择图片但范围无图片 | 提示没有图片 |
| 导出中用户继续新增数据 | 当前导出按创建任务时确定的数据范围执行 |
| 导出失败 | 可重试，不影响原数据 |
| 下载链接过期 | 可重新生成 |
| 用户删除原记录 | 后续新导出不再包含已删除记录 |

## 十四、业务规则与约束

1. 图片是业务记录附件，不替代结构化饮食数据。
2. 图片上传失败不能导致已正确填写的饮食记录整体丢失。
3. 用户只能导出自己有权访问的数据。
4. 数据导出默认不包含密码、Token、内部系统字段等安全信息。
5. 导出中的数值口径应与页面当前查询口径一致。
6. 图片与记录之间必须可对应。
7. 后续 AI 导出只能调用同一套导出能力，不能另外拼一套数据。
8. 后续 AI 导入的数据写入后，也必须能正常参与这里的导出。

## 十五、验收标准

- 新增饮食时可上传图片；
- 一条记录可关联多张图片；
- 图片失败不影响饮食保存；
- 历史饮食可以查看关联图片；
- 用户可按时间范围创建导出；
- 可分别导出饮食明细与每日营养汇总；
- V1.5/V2 上线后可自动扩展身体和训练数据域；
- 勾选“包含图片”后，下载包中包含对应原始/可用图片文件；
- 导出包中的图片与记录可以对应；
- 用户之间数据严格隔离；
- 大导出任务有明确状态和失败处理。

## 十六、技术约束（简版）

- 图片使用对象存储类能力保存，不建议直接存入关系数据库大字段；
- 导出可采用异步任务，但产品层必须展示状态；
- 结构化数据格式应便于 Excel/数据分析工具读取；
- 完整备份可打包结构化数据与媒体文件；
- 统一复用现有鉴权和用户数据隔离规则。
