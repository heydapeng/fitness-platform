# Fitness Nutrition Platform — PRD V1.5：身体数据与趋势

## 一、版本概述

V1/V1.1 解决了“今天吃了什么”，但用户仍然需要回答另一个问题：

> “我这样吃了一段时间，身体到底发生了什么变化？”

V1.5 增加身体测量记录与趋势分析，将营养摄入与体重、体脂、围度变化建立可观察关系。

## 二、用户核心问题

- 我的体重最近是在下降、维持还是上升？
- 单日体重波动很大，能不能看周平均趋势？
- 我的体脂和腰围是否同步变化？
- BMI、BMR、TDEE 是什么，系统怎么算出来的？
- 我过去的测量值能不能按日期查看和修正？

## 三、版本目标

1. 支持按日期记录身体指标；
2. 支持体重趋势和周平均；
3. 支持体脂、围度等多指标历史；
4. 提供 BMI/BMR/TDEE 等派生指标展示；
5. 派生指标需可解释，不覆盖原始测量事实；
6. 为后续训练、教练和 AI 提供可靠身体数据底座；
7. 支持用户可选上传身体进度照片，形成“数值变化 + 视觉变化”的长期记录。

## 四、功能范围

- 身体数据首页；
- 新增/编辑/删除身体测量；
- 体重、体脂、肌肉量、腰围、胸围、臂围、大腿围；
- 历史记录；
- 趋势图；
- 周平均体重；
- BMI；
- BMR/TDEE 基础展示与说明；
- 与当前营养目标的基础关联展示；
- 身体进度照片（可选）；
- 身体数据可纳入 V1.2 用户数据导出。

本版本不自动修改用户营养目标，不根据体重变化强制推荐减脂/增肌方案。

## 五、身体数据首页

### 1. 数据概览

顶部卡片建议展示：

- 最新体重；
- 相比上次变化；
- 近 7 天平均体重；
- 近 30 天变化；
- 最新体脂率（如有）；
- 当前 BMI（如基础资料完整）。

### 2. 趋势图

支持指标切换：

- 体重；
- 体脂率；
- 肌肉量；
- 腰围；
- 胸围；
- 臂围；
- 大腿围。

支持时间范围：

- 7 天；
- 30 天；
- 90 天；
- 自定义日期范围。

### 3. 趋势展示规则

- 原始测量点与趋势线区分；
- 没有足够数据时不展示误导性趋势结论；
- 单日多次记录时可保留全部记录，但趋势默认使用当日最新值或日均值，产品口径必须固定。

## 六、新增身体测量

### 1. 入口

- 身体数据首页“记录身体数据”；
- Dashboard 快捷入口（可选）。

### 2. 字段

- 记录日期：必填；
- 体重 kg：核心字段；
- 体脂率 %：可选；
- 肌肉量 kg：可选；
- 腰围 cm：可选；
- 胸围 cm：可选；
- 臂围 cm：可选；
- 大腿围 cm：可选；
- 备注：可选。

### 3. 校验

- 数值必须为合理正数；
- 百分比必须在合理范围；
- 对明显异常跳变可给出提示，但不应在合理范围内强制阻止用户保存真实测量；
- 至少填写一个有效身体指标。


## 七、身体进度照片

### 1. 功能定位

部分健身用户会定期拍正面、侧面、背面照片观察身材变化。照片属于身体记录的可选附件，不要求每次测量都上传。

### 2. 上传入口

- 新增身体测量时；
- 身体数据首页“添加进度照片”；
- 历史身体记录详情中补传。

### 3. 照片信息

每组进度照片可记录：

- 日期；
- 正面照片；
- 侧面照片；
- 背面照片；
- 自定义其他照片；
- 备注。

### 4. 对比查看

用户可选择两个日期进行对比：

- 左右并排查看；
- 同一拍摄方向优先配对；
- 同时显示两个日期的体重、体脂、腰围等关键数值；
- 不自动对身体外观做医学或价值判断。

### 5. 隐私规则

- 身体照片默认仅本人可见；
- 教练查看必须单独纳入授权范围；
- 数据导出时只有用户主动勾选“身体进度照片”才包含；
- 不默认用于公开展示。

## 八、身体数据导出联动

身体数据接入 V1.2 的“我的数据”能力。用户可按时间范围导出：

- 原始测量值；
- 周平均等基础趋势数据；
- 备注；
- 身体进度照片（可选）。

后续 V5 Agent 可通过同一导出能力响应“把我最近半年体重、腰围和身材照片导出来”，AI 只负责理解用户意图和选择导出条件。

## 九、身体记录历史

### 1. 列表字段

- 日期；
- 体重；
- 体脂；
- 肌肉量；
- 腰围；
- 主要变化值；
- 备注；
- 操作。

### 2. 搜索与筛选

- 日期范围；
- 指标是否有值；
- 分页或按月分组。

### 3. 编辑与删除

- 用户可修正录入错误；
- 修改后趋势图即时刷新；
- 删除前二次确认；
- 删除原始测量后，相关派生指标和趋势重新计算。

## 十、BMI / BMR / TDEE 展示

### 1. 产品定位

这些是辅助理解指标，不作为医疗诊断，也不自动替用户决定目标。

### 2. BMI

在有身高和体重时可计算并展示：

- 当前 BMI；
- 使用的身高和体重；
- 简短公式说明。

### 3. BMR / TDEE

只有在必要基础资料完整时展示。

页面应说明：

- 这是估算值；
- 使用的计算方法/版本；
- 活动水平等参数会影响结果；
- 不代表精确医疗测量。

### 4. 历史解释

如果算法未来调整，系统不应让旧页面结果“无说明地变化”。产品至少要能说明当前采用的算法口径；如未来保存历史派生值，应保留算法版本。

## 十一、饮食与身体数据关联

V1.5 可提供轻量关联，不做自动因果推断。

示例：

- 近 7 天平均摄入 vs 近 7 天平均体重；
- 当前营养目标与最近体重趋势并列展示；
- 提示“体重受水分、盐分、训练等多因素影响”。

禁止展示：

- “你这周胖了是因为昨天多吃了 X kcal”这类未经证实的因果结论。

## 十二、空状态与异常

| 场景 | 系统行为 |
| --- | --- |
| 从未记录身体数据 | 展示添加第一条记录引导 |
| 只有 1 条记录 | 展示当前值，不输出趋势判断 |
| 基础资料缺少身高 | BMI 显示“资料不完整” |
| BMR/TDEE 参数不完整 | 不计算或明确提示补充资料 |
| 测量值异常跳变 | 提醒用户确认，但合理范围内允许保存 |
| 删除最新记录 | 自动回退到上一条作为最新值 |

## 十三、业务规则与约束

1. 原始测量值是业务事实，应优先保存。
2. 派生计算不能替代或覆盖原始数据。
3. 趋势口径必须稳定并可解释。
4. 用户修改历史身体数据后，趋势和派生值应重新计算。
5. 身体数据属于敏感个人业务数据，默认仅用户自己可见。
6. V3 教练访问身体数据必须经过用户授权。
7. 后续 AI 回答身体数据问题时必须从业务数据读取，而不是依赖对话记忆猜测。

## 十四、验收标准

- 可新增至少一条体重记录；
- 可同时记录体脂和围度；
- 历史列表按日期正确展示；
- 编辑/删除后趋势图同步变化；
- 支持 7/30/90 天趋势；
- 周平均体重口径稳定；
- 基础资料完整时能展示 BMI；
- BMR/TDEE 有清晰估算说明；
- 用户之间身体数据完全隔离；
- 可上传身体进度照片并按日期回看；
- 可选择两个日期查看身体照片与关键数值对比；
- 身体数据和照片可通过“我的数据”按范围导出。

## 十五、技术约束（简版）

- 原始身体记录持久化；
- 派生指标优先按统一服务计算；
- 日期仍使用用户业务日期概念；
- 为后续教练授权和 AI Tool 查询预留稳定业务接口。
